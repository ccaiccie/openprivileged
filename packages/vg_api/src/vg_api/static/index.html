Active Directory integration
Configure the directory used for sign-in and group-based access. One AD integration is supported. LDAPS certificate and hostname validation are always required. Group discovery and sign-in use read-only AD access. Optional privileged-account creation is a separate, explicitly approved workflow below.
When enabled, AD resolves transitive membership under the group search base. Primary-group membership is not used for authorization; use explicit security-group membership. Incomplete or unavailable directory results deny access.
AD groups and application roles
Load security groups from the configured group search base, then add a mapping and choose its roles. Group membership remains managed in AD. Multiple mappings combine permissions. Selecting a role does not grant domain administration.
Supported roles: superadmin, admin, technician, approver, auditor. Device IDs must exist in this customer scope. Your current AD identity must retain superadmin access. Saving changes signs everyone out; sign in again afterward. The reader password is encrypted at rest and never returned to this page.
Technician equipment accounts
Each technician uses their regular AD account to sign in. Equipment connections use a separate AD account prefixed with a.: joe.bloe → a.joe.bloe. The privileged account must exist in AD; technicians must not receive its password.
Choose manual creation by your AD team (no account-creation access for OpenPrivileged), or opt in to delegated creation in a dedicated OU. Do not grant Domain Admin or domain-wide write access. A separate writer needs Create User objects and Reset Password rights in that OU, plus only the attributes required for the account. Rotation later needs Reset Password for enrolled accounts; device-group membership is a separate, narrowly scoped delegation.
This creation workflow stages a disabled account with an encrypted password. It does not yet enroll the account into rotation, enable SSH access, or grant device privileges. After separate approval, an operator must verify ownership, assign approved equipment rights and enable the staged account, then explicitly enroll it and test managed access. Enrollment requires an already-enabled account; this form does not perform activation or enrollment.
